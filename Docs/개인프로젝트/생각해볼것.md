








1. 어떤 인력들을 팀에 배치할 지
- 기획자
- 개발자
- 기획 및 개발 중간 조율자
- 코드컨벤션 및 오류 검수자
- 빌드 및 배포, 최종 검수자
- 배포 이후 서비스 관리자

2. 업무마다 어떤 프로세스로, 어떤 인력들이 붙어서 진행해야 하는 지

- 중간 조율자는 나와 대화하여 기획과 개발에 전달 및 그들의 의견 나에게 전달
- 코드 및 오류 검수자는 팀의 규칙을 알고 개발자와 작업 및 검수

- 준비 : 기획자, 개발자, 중간조율자에게 게임제작내용 전달

- 기획 : 기획자는 중간 조율자를 통해 나에게 내용 전달하며 기획
- 기획 : 기획 후 개발자에게 전달하고 개발 시작, 중간 조율자와 지속적 소통

- 개발 : 개발 내용 오류 검수자와 공유하여 지속적 검수
- 개발 : 개발 완료 후 최종 검수자에게 전달

- 최종 검수 : 최종 검수자는 나와 소통하며 검수
    - 문제 X : 빌드 및 배포
    - 문제 O : 중간 조율자를 통해 기획 및 개발에 전달
- 최종 검수 : 문제가 된 상황과 이유에 대한 피드백 나와 상의 후 전달

- 서비스 : 시장 반응 확인 후 나에게 전달 피드백 확인후 나는 수정 여부 결정 및 내용 전달

3. 고정적인 업무(작업일지 등)는 어떤 것이 있고, 어떤 상황에 해야 하는지
- 이슈 : 이슈는 내용 승인 시 추가
- PR : 이슈와 동일한 내용인지 확인 후 올림
- 머지 : 이슈와 PR, 작업내용 검토 후 문제 없으면 나에게 내용전달
- 작업일지 : 하루 1회 작업내용 퇴근전 작성

## 전제조건

1. 팀 프로젝트로 게임 제작을 진행한다.
2. 나는 프로젝트 리더(PD)
3. 내가 원하는 인력(담당자)을 팀에 배치할 수 있음.
4. 룰이나 고정 업무 등을 내 마음대로 지정할 수 있음.
5. 업무 프로세스(인력 단위)를 내 마음대로 지정할 수 있음.
